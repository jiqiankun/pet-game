# 美术资源生产工作流

## 适用边界

这是当前项目的轻量 SOP：Markdown 清单 + Git + 已有 PowerShell 脚本。它不创建数据库、DAM、独立任务系统或新的运行时依赖。新增资源必须仍符合游戏配置和前端实际加载方式。

## 生命周期

`PLANNED → GENERATING → GENERATED → REVIEWED → INTEGRATED → VERIFIED`

`REJECTED` 为终止状态：保留候选图和简短原因，重新生成时创建新的候选版本。历史记录中的 `planned / generating / qc_pending / accepted / exported` 分别映射为 `PLANNED / GENERATING / GENERATED / REVIEWED / INTEGRATED`；不要再混用两套状态。

## 标准 SOP

| 阶段 | 输入与操作 | 输出 | 通过条件与失败处理 |
|---|---|---|---|
| 1. 登记 | 填写资源类型、ID、用途、数量、特殊要求；读取配置与 `asset-manifest.md` 查重。 | `PLANNED` 资源记录、正式路径、候选目录。 | ID、用途和使用页明确；已有可复用资源则停止生成，直接复用。 |
| 2. 归类 | 判断为 `SOURCE`（需生成）、`DERIVED`（由已有图派生）或 `NO_ASSET_REQUIRED`（CSS/SVG/Phaser 表现）。 | 最小资源集合。 | 不为每个技能、野怪或 UI 状态重复生成同义素材。归类不清时先查实际接入点。 |
| 3. 定规格 | 以资源管理表锁定尺寸、透明、裁切、文件名和实际加载代码；首次引入新视觉域时先做 1～3 个风格锚点。 | 可评审的 Prompt 与处理计划。 | 与既有类型相同则不重做风格锚点；规格不能凭生成结果倒推。 |
| 4. 生成候选 | 用对应模板生成候选；宠物按最多 3 只一批、统一图标/VFX 可按同规格一批、背景/事件按单张验收。记录模型、比例、关键提示词与后处理。 | `GENERATED` 候选源图，存入现有 `docs/art/*-candidates/`。 | 有文字、水印、裁切、风格漂移、假透明或主体不清晰时标 `REJECTED`，重生该候选；不要修补成正式图。 |
| 5. 后处理与派生 | 透明绿幕用 `remove-chroma-key.ps1`；图标、VFX、tileset 按既有专用脚本派生。 | 规格正确的正式候选 PNG。 | 先运行脚本自身校验，再检查透明角、主体边界和尺寸。脚本不能替代视觉验收。 |
| 6. 审核 | 按质量标准做自动检查、contact sheet 和人工视觉检查。 | `REVIEWED` 资源与 QC 记录。 | 任一硬性规格或人工关键项不通过即退回阶段 4 或 5。 |
| 7. 接入 | 将资源放入既有正式目录；仅在已有共享映射或加载场景中补最小映射，替换占位使用点。 | `INTEGRATED` 代码/资源改动。 | 没有代码引用、加载键或业务配置对应关系时不得宣称完成。 |
| 8. 实机验证与归档 | 在真实页面/地图/战斗触发场景中检查，保存必要截图；更新清单、QC 和状态。 | `VERIFIED` 清单记录。 | 发现遮挡、缩放模糊、切图缝隙、错误映射则回到阶段 3～7 的最早问题点。 |

## 已验证的工具使用规则

| 工具 | 适合做什么 | 不可替代的检查 / 注意事项 |
|---|---|---|
| `remove-chroma-key.ps1` | 将稳定纯色（本轮为绿幕）候选转换为透明 PNG，并校验边缘和可见像素。 | 边缘绿幕不足会拒绝处理；仍须肉眼检查白边、色溢和主体留白。 |
| `derive-pet-icons.ps1` | 从已审核宠物立绘派生 256/128/64 图标及既有野怪缩放图。 | 只对已通过的肖像运行；它会更新派生目标，先核对输入和 Git 差异。 |
| `derive-item-icons.ps1` / `split-ui-icon-sheet.ps1` | 从底图或图标表按既有命名批量导出。 | 目标已存在时脚本会拒绝覆盖；需要替换时先人工确认资源版本。 |
| `build-vfx-sprite-sheet.ps1` | 将一张透明特效主体统一为 4 帧 `256×256` 横向精灵表。 | 固定 12 FPS、非循环、中心锚点；检查每帧是否表达“起势—峰值—余波—消散”。 |
| `build-tilesets.ps1` | 把本项目四个 2×2 源图导出为 `128×32` tileset，并生成预览。 | 该脚本会覆盖既有四套 tileset 和兼容文件，只能在明确替换这些资源时运行；必须在地图内检查接缝。 |
| `prepare-raster-asset.ps1` | 统一不透明背景/场景图的最终尺寸。 | 采用覆盖缩放，会裁切；禁止用于透明角色、NPC、道具和 VFX，除非人工确认裁切安全。 |

## 本轮复盘的固定经验

- 先以风格锚点定画风，再小批量生成，稳定性高于一次生成大量角色。
- 角色的“3/4 左前、全身居中、10% 留白、2～4 主色、统一光源”是避免外观漂移的关键固定块；差异应来自剪影、元素材质和定位，而不是改变画风。
- 透明 PNG 适合角色、props、图标和 VFX；区域背景、主页背景、事件插画应保持不透明场景画面。生成器没有可靠 alpha 时，先生成干净绿幕，再由脚本抠图。
- 技能按视觉语义映射到 31 个 VFX 模板，而非按 85 个主动技能各做一张图；野怪直接由宠物图标派生。这是当前规模下最小且足够的复用粒度。
- AI 生成的 “+” 号、伪文字、水印、杂乱背景、边缘色溢和主体贴边不能通过后处理掩盖，应拒绝候选并重生。
- Tileset 的尺寸校验不足以证明可用：本项目只接受实际 Tiled 地图预览与运行时都无接缝的图集。

## 重新生成或替换的规则

正式文件名不附加 `v2`、`final2` 等后缀；版本由 Git 和清单的 `version`/变更说明管理。候选图可使用 `_v01`、`_v02` 方便比较。替换正式资源前必须先完成同一类型 QC，并确认所有实际加载点仍指向该规范路径。
