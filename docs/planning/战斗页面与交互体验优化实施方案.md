# 战斗页面与交互体验优化实施方案

> **历史方案说明（2026-08-19）：** 当前战斗改造以桌面重构需求、详细任务规划和阶段 0 D0-02 为准；本轮不实施手机/平板适配，且手动/自动战斗均允许共享库存中配置为战斗可用的恢复/复苏道具。本文冲突段落只作历史问题记录。

**适用项目：** 宠物精灵游戏第一阶段
**依据：** 《宠物精灵游戏第一阶段需求设计文档 V1.0》《宠物精灵游戏第一阶段技术方案说明 V1.0》、`docs/architecture/ARCHITECTURE.md`、`docs/development/FRONTEND_STANDARDS.md`、`AGENTS.md` §7 固定规则
**目标：** 在不改变战斗规则/数值/技能/地图玩法的前提下，系统性优化**战斗页面展示、页面联动、手动技能操作与整体战斗体验**。

---

## 0. 文档定位

本文档聚焦**战斗链路**优化：

> 进入战斗 → 观察局势 → 选择操作 → 选择技能/宠物/物品 → 确认行动 → 观看战斗反馈 → 下一回合 → 战斗结算 → 返回地图

核心体验目标（六点）：

> **看得懂 · 点得快 · 少误触 · 有反馈 · 能思考 · 不拖沓**

并保证 PC / 平板 / 手机端一致的核心战斗逻辑与各自良好的响应式表现。

> 代码修改需在本文档审核通过后按优先级（§P0/P1/P2）执行。禁止在方案未确认前改动代码。

## 1. 当前实现分析

### 1.1 战斗是独立路由，非 Overlay

- 战斗页为 `/battle`（[BattleView.vue](file:///e:/jqk_code/pet-game/frontend/src/views/Battle/BattleView.vue)），是 MainLayout 顶部导航的一个 `<RouterLink>`。
- 地图遇敌：ExploreView 弹「遭遇野生宠物」确认 → `battleStore.startMapEncounter()` → `router.push('/battle')`。
- Boss 战：BossView `startBattle()` → `router.push('/battle')`。

### 1.2 地图进入战斗发生路由跳转 → 地图销毁

- 跳转 `/battle` 会卸载 ExploreView → `game.destroy(true)`（[ExploreView.vue onBeforeUnmount](file:///e:/jqk_code/pet-game/frontend/src/views/Explore/ExploreView.vue#L308)）。
- 玩家坐标/方向/相机仅存于 MapScene 本地，不入 store → 切页即丢。

### 1.3 战斗结束返回地图

- `handleLeave()` 仅 `battleStore.leaveBattle()`（清空战斗 store），**不自动返回地图**。
- 需用户手动导航；返回后地图重新初始化、从出生点重生。
- 无「战斗结束 → 恢复地图」的自动链路。

### 1.4 战斗 HUD 布局（当前）

单页纵向堆叠：头部（回合/类型/速度/自动）→ 自动战斗面板 → 敌方卡片行 → 目标提示 → 我方卡片行（含行动面板）→ 回合提交 → 事件日志 → 结算面板/调试面板。

- 行动面板直接内嵌在**每个存活上场宠物卡片**内（技能按钮 + 防御 + 捕捉/逃跑 + 换宠）。
- 每个技能是一个小按钮（图标 + 名称 + CD 数字）。

### 1.5 技能操作方式（当前）

- 点击**单体敌方技能** → 进入 `targeting` 状态 → 点敌方单位确认。
- 点击**己方/全体技能** → 直接收集行动。
- 点击**防御/捕捉/逃跑/换宠** → 直接收集行动。
- `pendingActions` 在 battleStore 中，`setAction`/`getAction` 管理；可覆盖（同一单位重复设置覆盖）。
- **无「技能确认」面板**：技能信息（威力/属性/效果）仅靠 hover `title` 属性展示。

### 1.6 技能数量与来源表现

- 技能来源（SkillConfig）：`INNATE`（自身）/ `BOOK`（技能书）；类型 `ACTIVE`/`PASSIVE`。
- 宠物自身主动技能展示在行动面板；**技能书主动**（slot 5~6）与被动在 PetView 管理，战斗内 `UnitSnapshot.skillIds` 已含装备生效的技能。
- 冷却：`UnitSnapshot.cooldowns`（skillId → 剩余回合）。

### 1.7 已具备的能力（复用，不重复开发）

| 能力 | 现状 |
|---|---|
| 换宠 | 行动面板「换上 X」按钮（SWITCH 行动） |
| 防御 | 行动面板「防御」按钮 |
| 捕捉 | 野生战「捕捉」→ 选球 → 点目标；`loadCaptureRates` 实时刷新 |
| 逃跑 | 野生战「逃跑」按钮（用户裁决：必定成功、同战败结算） |
| 自动战斗 | `toggleAutoBattle` + 策略面板 + `/auto` 接口 |
| 战斗速度 | 1x / 2x / 3x（`battleSpeed`，影响自动间隔与 VFX 时长） |
| Buff/Debuff | `UnitSnapshot.statuses` 五类模型 + 图标 + 剩余回合/叠层 |
| 行动顺序 | `ACTION_ORDER` 事件 → `actionOrder` 条 |
| 事件日志 | `eventLog`（describeEvent 翻译） |
| 战斗结算 | `settlement` 面板（经验/金币/掉落/HP 回写/捕捉/战败/胜利互动） |
| 克制标记 | `BattleEvent.elementRelation`（DAMAGE 事件）与日志文本 |
| 捕捉率 | `/api/wild/battles/{id}/capture-rates` 返回精确数值 |
| VFX | `BattleView` 内 `playVfxForEvents` 按事件播放雪碧图动画 |

### 1.8 响应式

全局 `@media (max-width: 768px)` 底部导航 + BattleView 内少量缩放（unit-card min-width 140px、event-log max-height）。整体为「桌面优先、移动端粗略适配」。

### 1.9 VFX / 音效 / 动画资源

- VFX：`public/assets/fx/{elemental|combat}/vfx_*.png` 雪碧图，BattleView 用 CSS background-sprite 播放（`battle-vfx-frames` 4 帧）。
- 音效：**当前无音频系统**（无音效资源、无 AudioManager）。
- 动画：仅 VFX 播放 + 少量 CSS transition；无伤害飘字、无浮层过渡。

### 1.10 已完成与规划中的战斗功能

- 已完成：回合制引擎、状态五类、被动体系、自动战斗、Boss 难度/快照/阶段、捕捉、逃跑、战败零惩罚、精英、动态难度、等级压制、调试信息。
- 本次不新增战斗机制，仅做体验层优化。

## 2. 当前问题

1. **整页路由跳转**：战斗离开地图、地图销毁、返回后重生（最严重，破坏"我在同一世界"感受）。
2. **技能信息缺失**：技能只显示名称+CD，无属性图标、无克制提示、无威力/效果预览；玩家需记忆属性克制。
3. **技能不可用无原因**：变灰但不说为什么（CD/沉默/蓄力/目标非法/战斗结束）。
4. **无技能确认**：单击即收集行动，误触难返回（虽有覆盖，但无"确认/取消"直觉）。
5. **换宠/背包/捕捉入口分散**：换宠是卡片内小按钮、背包不存在于战斗、捕捉是独立按钮流，层级不一致。
6. **无战斗背包**：战斗内无法使用恢复道具（当前自动战斗可配置 autoUseRecoveryItem，但手动无入口）。
7. **伤害反馈弱**：只有日志文本，无伤害飘字；克制/暴击/免疫仅靠颜色/文字，不直观。
8. **状态详情缺失**：只能看到状态名+回合，长按无详情。
9. **捕捉难度过精确**：显示 `63.42%`，不符合"感受留生一击+控制提升捕捉"的游戏化目标。
10. **移动端粗糙**：技能按钮密集、点击区小、无 Bottom Sheet、无单手友好布局。
11. **无 Enemy Intent / Boss 蓄力提示**：无法预判敌方意图，战术决策信息不足。
12. **无渐进式教学**：状态/机制首次出现无解释。

## 3. 需要保留的实现（不重复开发）

- **后端全部战斗逻辑**（BattleEngine、DamageCalculator、CaptureCalculator、状态被动、自动 AI、Boss 阶段、结算）——前端只展示，不重算。
- **battleStore**（快照/行动/结算/捕捉率/自动/速度/事件日志）——在其上收敛，不推翻。
- **settlement 结算面板**（经验/金币/掉落/HP 回写/捕捉/战败）——保留，仅调整触发与展示节奏。
- **捕捉率接口**（`/api/wild/battles/{id}/capture-rates`）——精确数值保留给内部，前端映射为模糊等级展示。
- **自动战斗 / 速度 / 行动顺序 / 事件日志 / VFX 机制 / labels.ts / game-assets.ts**——全部复用。
- **View 布局素材**（立绘、状态图标、技能图标、VFX 雪碧图）——复用。

## 4. 需要修改的实现（仅前端为主）

### 4.1 页面联动：战斗改为 BattleOverlay（P0）

- 新增 `stores/overlay.ts`（轻量 OverlayManager，仅维护战斗+少量浮层栈），复用 Pinia。
- ExploreView 遇敌确认后：`overlayStore.open('BATTLE', {...})`，**不再 `router.push('/battle')`**。
- 地图实例不销毁；MapScene 增加 `explorationPaused` ＋ `cmd:set-exploration-paused`（战斗打开时暂停玩家移动/野怪 AI/接触检测）。
- BattleView 支持「Overlay 模式」：由 OverlayManager 挂载时全屏覆盖地图；保留「独立模式」（直接访问 `/battle` 用于测试战斗/开发者入口，不删除路由）。
- 战斗结束：走统一 BattleResult 回写 → `overlayStore.close('BATTLE')` → 恢复探索。
- 避免重复触发 Encounter：复用 `wild.engaged` + 增加 `encounterLock`（恢复后短暂冷却）。

### 4.2 战斗 HUD 布局重构（P0）

目标布局（纵向）：

```text
顶部  敌方 HUD（居中卡片，含意图/蓄力/精英/Boss 标识）
中部  Battle Arena（立绘 + 伤害飘字 + VFX 层）
中下  我方 HUD（各存活宠物缩略卡片：名称/等级/HP 条/盾/状态）
底部  Action Control（一级菜单：攻击 / 宠物 / 背包 / 战术）
```

- 行动面板**从宠物卡片内移出**到底部统一控制区，避免上行滚动找按钮。
- 我方 HUD 卡片负责：选目标、状态展示、HP/盾条；点击/长按查看详情。

### 4.3 一级操作菜单统一（P0）

```text
攻击     → 打开当前出战宠物的技能面板（SkillPanel）
宠物     → 打开换宠 BottomSheet（PetSwitchPanel）
背包     → 打开战斗背包（BattleBagPanel）
战术     → 防御 / 逃跑 / 自动战斗 / 战斗设置（动态隐藏 Boss 禁用的"逃跑"等）
```

- 不固定为「攻击/背包/宠物/逃跑」：Boss/剧情战可隐藏或禁用"逃跑"。
- 每个一级项带图标+文字，触控区 ≥44px。

### 4.4 技能按钮信息增强（P0）

每个技能按钮展示（由 `/api/game/config/skills` 完整字段驱动，**扩展前端 `SkillConfigView`**）：

```text
[属性图标] 技能名
克制/效果标记（↑ 效果较好 / ↑↑ 拔群 / ↓ 较弱 / × 无效）
CD 或"可用"标识
```

- 属性图标：复用 `elementIconUrl`。
- 克制标记：按「技能属性 vs 当前选中/首个敌方目标属性」实时计算（见 §4.5 数据准备）。
- 本属性加成（技能属性=宠物属性 ×1.20）可一并标记。

### 4.5 技能不可用原因（P0）

- 冷却中 → `CD 2`，tooltip「还需 2 回合」。
- 宠物被沉默 → 「沉默中，无法使用技能」。
- 蓄力中 → 「蓄力中」。
- 目标非法（治疗技能无受伤队友 / 复苏无倒下宠物）→ 明确文案。
- 战斗结束 / 自动战斗进行中 → 对应提示。
- 实现：诊断函数 `skillUnavailableReason(unit, skill)`，返回 `{ blocked, reason }`，按钮禁用时展示原因。

### 4.6 技能确认/返回机制（P0）

- 单击技能 → **选中态**（高亮），显示轻量预览条（非大型 Modal）：目标类别、克制标识、简要效果、CD。
- 单体技能 → 进入目标选择，高亮合法目标、压暗非法目标。
- 再次点击目标或确认按钮 → 收集行动。
- 「取消/返回」按钮（或 ESC）→ 撤销未提交动作。
- 设置项「技能单击立即释放」：熟练玩家可开启，跳过二次确认（默认开启确认）。
- 复用 `pendingActions/setAction/getAction`，不新建行动状态。

### 4.7 换宠（P0）

- 点击「宠物」→ 打开 **PetSwitchPanel（Bottom Sheet）**，不离开 BattleOverlay。
- 列表展示：名称/等级/HP 条/是否倒下/状态/与当前敌人属性关系（优势/劣势/普通）/当前出战标识。
- 点击候补 → 确认换宠（收集 SWITCH 行动）。

### 4.8 战斗背包 BattleBagPanel（P0）

- 点击「背包」→ 打开 **BattleBagPanel**，只展示战斗相关物品，按分类：
  `恢复 / 复苏 / 状态恢复 / 强化 / 捕捉 / 其他可战斗使用`。
- 自动过滤：装备、素材、任务道具、战斗中不可用物品。
- 不可用物品说明原因（如"仅战斗外使用"）。
- 使用物品需选目标（我方存活宠物）→ 确认 → 收集行动（`ITEM_USED` 事件驱动反馈）。
- 复用现有 `useInventoryStore` / `/api/inventory` 数据，不新开完整背包。

### 4.9 捕捉操作增强（P0）

- 满足捕捉条件时动态增强入口与提示（`✦ 可尝试捕捉`）。
- 捕捉难度展示：把 `/capture-rates` 精确数值映射为模糊等级：
  `极难 / 困难 / 普通 / 较容易 / 很容易`（阈值由前端映射，不改变后端）。
- 捕捉流程收敛在 BattleOverlay 内（选球 → 点目标 → 捕捉动画 → 结果），不跳页。

### 4.10 伤害飘字与反馈（P1）

- Arena/VFX 层叠加伤害飘字：普通 `-86`、暴击 `CRIT! -143`、克制 `效果拔群 -128`、抵抗 `效果较弱 -42`、恢复 `+120 HP`、护盾 `Shield -62`、无效 `IMMUNE`、Miss `MISS`。
- 由 `BattleEvent`（value/critical/elementRelation/type）驱动，**颜色仅作辅助，必配文字/图标**。
- 事件日志折叠为「战斗日志」按钮，默认只看短消息区。

### 4.11 状态详情（P1）

- 长按（手机）/ Hover 或 ⓘ（桌面）状态图标 → 状态详情浮层。
- 新增只读接口 `/api/game/config/statuses`（后端，读 YAML 状态配置），前端展示名称/类别/描述/剩余回合/叠层。
- "点击 = 操作、长按 = 查看详情" 统一约定；桌面提供 Hover/右键/ⓘ 等价入口。

### 4.12 自动/手动快速切换（P1）

- HUD 常驻 `AUTO` 标识（自动战斗进行中），一键切换。
- 发现稀有宠物时一键关闭自动：当前安全动作结束后切回手动（复用现有 `toggleAutoBattle`，仅强化 HUD 入口与状态展示）。

### 4.13 Enemy Intent / Boss 蓄力（P2）

- 敌方 HUD 增加意图提示：`⚔ 准备攻击 / 🛡 防御倾向 / ✨ 正在蓄力 / 💚 可能恢复`。
- 复用 `UnitSnapshot.charging`/`chargingSkillId`/`chargeRemaining` 与状态（防御/蓄力），不暴露确切数值。
- Boss 蓄力：`⚠ 强大的力量正在聚集……` 视觉/反馈，玩家获得反应回合（复用现有蓄力机制，不新写 Boss 特殊判断）。

### 4.14 渐进式教学（P2）

- 首次出现某状态/机制时，轻量解释条（如 `☠ 中毒：每回合损失少量 HP`）自动消失；再次出现仅图标。
- 复用 `questStore`/`tutorialState` 或本地 `labels.ts` 首次展示标记，不新增重型教程系统。

### 4.15 图鉴未知信息（P2）

- 未知敌人显示 `名字 Lv.? 属性：？`，随战斗/捕捉/图鉴解锁逐步开放（复用 `/api/pokedex` 图鉴状态）。
- 需先核对现有图鉴需求，避免与现有设计冲突。

## 6. 战斗状态流

```text
遇敌 → BattleOverlay 打开 → 战斗开始（battleStore.startMapEncounter）
  → [回合循环] 选行动 → 提交（submitActions）→ 后端算 → 快照返回 → 渲染反馈
  → 战斗结束（snapshot.finished）
  → 结算（settleBattle → settlement）
  → BattleResult 统一回写（地图/野怪/Boss/任务/图鉴）
  → BattleOverlay 关闭 → 恢复探索
```

> 全部后端裁定，前端只提交行动意图。

## 7. UI 状态流

- **Game State**（battleStore）：snapshot / settlement / captureRates / actionOrder / eventLog。
- **UI State**（组件内或 overlayStore）：`currentMenu`（一级菜单）、`currentSkillPanel`、`targeting`、`selectedBall`、`petSwitchOpen`、`bagOpen`、`tacticalOpen`、`settingsOpen`、`selectedPetId`、`statusDetail`、`fuzzyCaptureTier`。
- 关闭 Overlay 不丢 Game State；纯 UI 状态不入存档。

## 8. 技能操作流程

```text
点击"攻击" → SkillPanel（当前出战宠物技能）
  → 点击技能 → 选中态 + 预览条（克制/CD/效果）
    ├─ 单体 → 高亮合法目标 → 点目标 = 确认
    ├─ 己方/全体/自身 → 直接确认（或预览确认）
    └─ 取消/ESC = 撤销
  → 收集 action → "结束回合" 提交
```

## 9. 换宠流程

```text
点击"宠物" → PetSwitchPanel（Bottom Sheet）
  → 展示队伍（HP/倒下/状态/属性关系/当前出战）
  → 点候补 → 确认 → 收集 SWITCH 行动 → 关闭面板
```

## 19. 最终设计原则

所有优化围绕：

> **看得懂**（玩家第一眼理解战况）
> **点得快**（高频操作 1~2 次点击）
> **少误触**（危险/不可逆操作有确认）
> **有反馈**（技能/伤害/Buff/捕捉/换宠/结果均有反馈）
> **能思考**（属性/敌方意图/行动顺序支持决策）
> **不拖沓**（动画/跳转/多层菜单不拖慢回合节奏）

若某设计不能明显提升上述任一项，则重新评估是否值得开发。
