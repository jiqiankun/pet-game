# 2. 产品目标与体验原则

目标体验：玩家应始终感觉自己“待在同一个世界里”，只是偶尔打开背包、查看宠物、与
NPC 对话或进入战斗；关闭功能后立即回到原来的世界位置和状态继续冒险。

**R-004 \[MUST\]** 采用 World-Persistent
UI：世界/探索地图是游戏根节点，功能是“打开/覆盖”，而不是将玩家导航到与世界割裂的独立页面。

**R-005 \[MUST\]** 战斗是世界上的 Battle Context
与覆盖层，不得以销毁地图并跳转到独立 BattlePage 的方式形成明显页面割裂。

**R-006 \[MUST\]**
地图即桌面：探索画面必须长期保持为视觉主舞台，中央主要视野不得被常驻
HUD、标签和按钮占满。

**R-007 \[MUST\]**
系统负责让玩家知道方向，玩家负责决定怎么走；默认不得使用持续 GPS
路线、自动寻路或自动移动代替探索。

**R-008 \[MUST\]** 技术上允许分地图，体验上必须连续；地图切换应保留
HUD、任务追踪、世界状态、位置语义和旅行方向感。

**R-009 \[MUST\]**
地点必须值得被记住：主要地图必须具备明确地标、空间身份和与相邻地图可信的方向关系。

**R-010 \[MUST\]**
资源压力的目标是制造“继续深入还是返回安全点”的选择，而不是制造重复跑图、繁琐生存管理或惩罚性资源焦虑。

**R-011 \[MUST\]**
世界状态、玩家知识和任务剧情应联动；任务不应只是地图上独立的待办清单。

**R-012 \[MUST\]**
优先加深已有战斗、捕捉、宠物、技能、地图、任务、道具之间的联动，不因追求丰富而横向引入无必要的大型新系统。

# 3. 变更范围与明确不做

| **本轮包含**                                   | **本轮不包含**                         |
|------------------------------------------------|----------------------------------------|
| 桌面探索主界面、HUD、浮层/面板/对话/战斗层     | 手机版布局、触控交互、虚拟摇杆         |
| 地图连通、World/Region/Map 层级、Gateway、捷径 | 真正无缝开放世界 Streaming             |
| 世界地图、区域地图、小地图、导航与发现         | 自动跑图、持续 GPS 导航                |
| 城镇、营地、野外、安全点、快速旅行             | 重生惩罚型生存系统                     |
| 野外遭遇对象与战斗覆盖层衔接                   | 队伍宠物跟随玩家在探索场景中行走       |
| 任务/剧情/世界状态联动                         | 每日任务、运营活动、FOMO 实时玩法      |
| 昼夜/天气/轻量事件的低成本世界变化             | 复杂生态模拟、NPC 全日程模拟           |
| Map Contract、WorldGraph 校验与验收规则        | 为了扩地图数量而批量制作低价值重复地图 |

**R-013 \[MUST\]**
不得新增队伍宠物跟随、陪伴宠物在探索场景中行走等系统。

**R-014 \[MUST\]**
不得引入饥饿、疲劳、体温、装备耐久等生存资源，除非未来单独立项。

**R-015 \[MUST\]** 不得以“页面已经存在”为理由保留明显违背
World-Persistent UI 的强制跳页流程。

# 4. 桌面端总体页面与层级架构

> World Layer  
> ↓  
> HUD Layer  
> ↓  
> Interaction Layer  
> ↓  
> Panel Layer  
> ↓  
> Dialog Layer  
> ↓  
> Battle Layer  
> ↓  
> Effect / Notification Layer

**R-016 \[MUST\]** World Layer
常驻并承载探索地图、玩家位置、当前地图对象与世界状态；打开普通功能时不得销毁或重新初始化
World Layer。

**R-017 \[MUST\]** HUD Layer
只展示高频、当前决策相关信息；低频详情必须通过
Hover、Tooltip、侧边面板或大型 Overlay 按需展开。

**R-018 \[MUST\]** Panel Layer
支持桌面端浮动/靠边面板；最多允许有限数量轻量面板同时存在，避免模拟操作系统式多窗口。

**R-019 \[MUST\]** 大型深度管理 Overlay
应进行互斥管理；同一时间不应叠加多个遮挡大部分世界的深度界面。

**R-020 \[MUST\]** Dialog、Shop、Map、Pet Detail、Battle 等 Blocking
Context 打开时应锁定探索输入，并根据 Context 暂停世界模拟。

**R-021 \[MUST\]** Toast、Tooltip、地区名、任务更新等 Non-blocking
信息不得锁定玩家移动。

**R-022 \[MUST\]** 关闭最上层 UI
后必须恢复进入前的世界位置、朝向、相机状态、追踪任务和相关面板上下文。

# 5. 探索主界面与 HUD

推荐采用“四个信息岛 + 中央留白”的布局：四角/边缘承载轻量 HUD，中央
50%~60% 区域尽可能留给地图、玩家、NPC、遭遇对象和地标。

| **区域**  | **默认内容**                      | **行为**                                         |
|-----------|-----------------------------------|--------------------------------------------------|
| 左上      | 首发宠物/队伍摘要、必要状态       | 显示首发与异常摘要；详细队伍信息点击展开         |
| 右上      | 当前 Region/Map 名、轻量货币/资源 | 进入新区域时名称短暂强化，随后弱化               |
| 左下      | 当前追踪任务/主线目标             | 展示目标区域/下一步，不展示完整任务清单          |
| 右下      | 极简小地图                        | 北朝上，突出出口/营地/当前目标，避免雷达化       |
| 底部/边缘 | 少量快捷功能入口                  | 队伍、背包、任务、地图等；显示快捷键但不强制记忆 |

**R-023 \[MUST\]** 探索 HUD 不得常驻显示全部宠物
HP、全部道具数量、全部任务或所有野怪/NPC 标签。

**R-024 \[MUST\]**
当前区域名首次进入时可短暂强调，随后弱化为轻量位置文本。

**R-025 \[MUST\]** 任务 HUD
默认只突出一个当前追踪任务；主线可保留轻量存在感，但不得同时铺开大量支线。

**R-026 \[MUST\]** 小地图默认北朝上，与世界地图和区域地图统一方向语言。

**R-027 \[MUST\]**
普通野怪默认不作为小地图实时红点雷达展示；精英、已锁定目标或当前任务对象可按需显示。

**R-028 \[MUST\]** 获得道具、地图更新、任务步骤完成等采用
Toast/侧边轻反馈，普通情况不得使用阻塞式中央弹窗。

# 6. 输入、焦点与 Context Stack

| **操作** | **桌面默认行为**                              |
|----------|-----------------------------------------------|
| W/A/S/D  | 8 方向或连续方向移动                          |
| E        | 统一世界交互键                                |
| M        | 世界/区域地图                                 |
| Q        | 队伍快速面板                                  |
| B        | 背包                                          |
| J        | 任务                                          |
| Esc      | 关闭/返回最上层 Context；探索态下进入系统菜单 |
| 鼠标左键 | 选中对象、操作 UI                             |
| Hover    | 轻量详情                                      |
| 右键     | 可选效率型上下文操作，不得成为唯一核心操作    |
| Shift    | 可选快跑；是否启用由最终地图尺寸和手感决定    |

**R-029 \[MUST\]** WASD
为桌面端默认移动方式；本轮不要求实现点击地面自动寻路。

**R-030 \[MUST\]** E 应统一承担 NPC
对话、宝箱、篝火、门、特殊装置等世界交互。

**R-031 \[MUST\]**
空间连续型普通地图出口宜直接步行触发；房门、洞穴、船、电梯、传送阵等明确“进入/使用”行为可要求
E。

**R-032 \[MUST\]** Esc 必须遵循 Context Stack，仅关闭/返回最上层
UI；战斗中 Esc 应先取消技能/目标选择，不得直接退出战斗。

**R-033 \[MUST\]**
深度面板打开时必须清空并冻结当前探索移动输入；关闭后不得继承打开前持续按键状态。

**R-034 \[MUST\]**
浏览器窗口失焦、切换标签、文本输入获得焦点时，应正确释放世界快捷键，避免角色持续移动或输入冲突。

**R-035 \[MUST\]**
鼠标点击远处对象只允许选中/查看或设为临时目标，不得自动将角色寻路过去。

**R-036 \[MUST\]** 探索镜头采用稳定软跟随，可有轻量 Look Ahead/Dead
Zone；不得频繁抖动或强制将角色死锁屏幕正中心。

**R-037 \[MUST\]**
探索场景不应提供大范围自由缩放或无限拖镜头，以免直接窥视整张地图和隐藏内容。

# 7. 队伍、宠物、背包、任务、商店等功能面板

## 7.1 队伍与宠物

**R-038 \[MUST\]** 点击/快捷键打开 Quick Team Panel，优先完成
HP/状态查看、队伍顺序、首发调整、简单恢复等高频操作。

**R-039 \[MUST\]** 宠物详细培养、技能、属性、成长等进入大型
Overlay；关闭后返回原探索状态，不进行路由跳页。

**R-040 \[MUST\]** 战斗换宠界面应复用同一队伍数据，但使用简化 Battle
Presentation，不得直接复用完整宠物管理页。

## 7.2 背包

**R-041 \[MUST\]**
背包以侧边或大型浮层形式打开，保留标签、筛选、滚动位置和最近查看上下文。

**R-042 \[MUST\]** 道具使用需要目标时，在当前 Overlay
内进入目标选择，不应跳转独立页面。

**R-043 \[MUST\]**
战斗背包与探索背包共享数据源，但战斗只展示允许在战斗中使用的道具。

## 7.3 任务

**R-044 \[MUST\]** 任务面板展示全部任务与阶段信息；探索 HUD
仅展示当前追踪目标。

**R-045 \[MUST\]** 任务中的地点名称应可直接联动打开地图并定位相应
Region/Map；Esc 按层级返回任务再返回世界。

**R-046 \[MUST\]** 任务步骤更新应优先使用轻量
Toast；章节结束、世界结构变化等才使用更明显反馈。

## 7.4 NPC、对话与商店

**R-047 \[MUST\]** NPC 对话发生于 World 上方，Explore HUD
自动弱化或隐藏；对话结束恢复。

**R-048 \[MUST\]** 普通商店优先通过 NPC/店面直接打开 Shop
Overlay，不要求为每个商店制作独立室内地图。

**R-049 \[MUST\]**
重要剧情建筑只有在确有探索、剧情或空间意义时才制作独立 Interior Map。

## 7.5 图鉴及其他深度功能

**R-050 \[MUST\]** 图鉴等深度功能可使用大型
Overlay；其地图联动应调用同一 World/Region Map，并以栖息地 Context
高亮信息。

# 8. 连通世界与 World Graph

**R-051 \[MUST\]** 世界采用 World → Region → Map
三层结构；不得无必要继续增加更深层级。

**R-052 \[MUST\]** 所有可探索 Map 必须作为 WorldGraph 节点；地图之间通过
Gateway/Connection 形成可信拓扑关系。

**R-053 \[MUST\]**
空间型连接默认遵循北↔南、东↔西的对称关系；特殊入口、楼梯、船、传送等使用语义型连接。

**R-054 \[MUST\]** 从某 Gateway 进入目标 Map 时，必须出现在对应 Target
Gateway 附近，且朝向与进入方向相符。

**R-055 \[MUST\]** 普通 Map
切换应采用轻量淡入/相机/音频过渡，不得每次出现强制 Loading
页面或“继续”按钮。

**R-056 \[MUST\]** 切图时 HUD、追踪任务、队伍状态和 World Context
不应重建或闪烁。

**R-057 \[MUST\]** 普通野外追击不得跨 Map 延续；剧情特殊追逐另行配置。

**R-058 \[MUST\]** Graph 是连接真相；World/Region Map
的展示坐标仅用于排版，不得反过来决定可达性和导航。

> WorldGraph = 世界是什么  
> PlayerKnowledge = 玩家知道什么  
> WorldState = 世界现在怎么样

# 9. 世界规模、Region 与地图生命周期

**R-059 \[MUST\]**
优先采用小世界、高复用、高变化、高记忆度；不得通过大量相似 Map
制造虚假规模。

**R-060 \[SHOULD\]** 建议完整核心世界控制在约 5~7 个主要 Region、20~35
张有意义的主要 Map、2~3 个城镇、5~7 个营地/安全节点。

**R-061 \[SHOULD\]** 每个 Region 建议 4~7 张主要地图，并允许 0~2
个真正隐藏地点；数量仅为内容预算，不得为凑数拆图。

**R-062 \[MUST\]** 主要 Region 通常承担一个章节生命周期：获知 → 抵达 →
建立方向 → 探索 → 激活营地 → 深入 → Boss → 世界变化 → 回访。

**R-063 \[MUST\]**
前期世界结构可较线性，中期出现可选分支，后期通过捷径与跨 Region
连接提高自由度。

**R-064 \[MUST\]**
主线可使用“分叉后汇合”而非维护多套完全独立剧情结局，以控制个人开发成本。

**R-065 \[MUST\]**
隐藏区域主要横向扩展世界，不得成为主线必经且不应在未发现前以“0/1
隐藏地点”泄露。

**R-066 \[MUST\]** Region
内应存在至少一个宏观记忆地标或独特空间语言，使玩家不依赖地图也能建立方向感。

# 10. Map Design Contract

新增一张地图前必须先完成设计契约，再进入
Tile/碰撞/坐标等实现。地图不是一张图片，而是世界图中的一个可验证节点。

| **字段/概念**        | **要求**                                                                                                                 |
|----------------------|--------------------------------------------------------------------------------------------------------------------------|
| Identity             | 地图为什么存在、主要玩法身份：ENTRY / EXPLORE / HUB / TRANSITION / DEEP_ZONE / BOSS / DUNGEON / SECRET / STORY / TOWN 等 |
| Emotion              | 玩家在此处的主要情绪目标，如安全、好奇、探索、压迫、释放                                                                 |
| Region               | 所属 Region，名称与层级必须统一                                                                                          |
| Primary Landmark     | 主要探索地图必须定义至少一个核心地标                                                                                     |
| Secondary Landmark   | 可选次地标，用于方向和内容组织                                                                                           |
| Gateway              | 所有入口/出口的语义名称、类型、方向、目标 Gateway                                                                        |
| Main Flow            | 首次主要探索路径与主线方向                                                                                               |
| Optional Flow        | 支路、可选风险、隐藏内容与捷径                                                                                           |
| Decision Point       | 重要岔路与路标需求                                                                                                       |
| Anchor               | NPC/任务/事件/地标绑定的语义锚点                                                                                         |
| Zone                 | 安全区、Spawn Zone、No-Spawn、Boss/剧情区域                                                                              |
| World State          | Boss、营地、道路、桥梁等长期状态变化                                                                                     |
| Dynamic Support      | 昼夜、天气、随机事件、动态生态是否适用                                                                                   |
| Battle Environment   | 普通战斗环境标签与 Boss 专用场景需求                                                                                     |
| Map Presentation     | 小地图、区域地图的节点/标签/隐藏规则                                                                                     |
| Return Use           | 首次、Boss 后、中后期回访的用途                                                                                          |
| Estimated Experience | 首次探索时长、纯通过时长、预计重复经过次数                                                                               |

**R-067 \[MUST\]** 主要探索 Map 缺少 Primary Landmark
时应视为设计缺陷，而非仅美术待补。

**R-068 \[MUST\]** Gateway
必须语义化命名并默认成对校验；单向连接必须显式声明。

**R-069 \[MUST\]** 地图内部 NPC、任务、事件优先绑定
Anchor/Zone，不应将裸像素坐标作为跨系统唯一语义。

**R-070 \[MUST\]** 入口附近必须存在 Arrival
Buffer，避免主动怪、重大触发器或反向出口立即抢夺控制权。

**R-071 \[MUST\]** 地图不得因“连接两个地方”而单独存在；纯连接 Map
应证明其过渡、叙事或视觉价值，否则合并。

**R-072 \[SHOULD\]** 普通探索 Map 的首次有意义体验可控制在约 3~8
分钟；核心大型 Map 可更长；纯通过时间应明显短于首次探索。

**R-073 \[SHOULD\]** 系统应支持对不可达 Map、Gateway
不成对、方向异常、缺少地标、过高遭遇密度等执行静态校验。

# 11. 地标、道路、方向感与空间记忆

**R-074 \[MUST\]** 每个 Region 必须具有鲜明视觉/地形/声音身份；同 Region
内各主要 Map 仍需有可辨识差异。

**R-075 \[MUST\]**
地点命名优先采用易理解、可联想到空间的名称，避免大规模“森林1/森林2”或过度晦涩的纯诗意命名。

**R-076 \[MUST\]** 任务、NPC
对话、地图和导航使用一致的地理语言，例如“翡翠森林 · 森林深处 · 巨石桥”。

**R-077 \[MUST\]**
道路、桥、洞口、栈道、铁轨等本身应承担空间记忆，不得所有 Map
只依赖相同土路+UI 箭头。

**R-078 \[MUST\]** 相邻主题差异较大的 Region
应通过过渡地形、声音、植被、光照或过渡 Map 建立合理变化。

**R-079 \[MUST\]** 城镇应小而清晰，优先一个明显中心和 3~5
个主要方向；野外承担探索，城镇承担功能与叙事。

**R-080 \[MUST\]**
安全点应具备一致“可识别但不必同造型”的视觉语言；系统规则统一，世界表现可因
Region 不同。

**R-081 \[MUST\]**
重要地标应被多次有意义地经过或回访，以积累玩家空间记忆。

# 12. 世界地图、区域地图与小地图

三层地图职责：World Map = Geography；Region Map = Topology；Mini Map =
Geometry。三者共享同一世界数据，但表现粒度不同。

## 12.1 世界地图

**R-082 \[MUST\]**
世界地图采用半地理、半拓扑的手绘式表现：看起来像真实世界，但允许尺度压缩。

**R-083 \[MUST\]** World Map 只突出
Region、城镇、主要安全点、大型地标、主要道路和当前任务，不显示每个
Map/宝箱/资源。

**R-084 \[MUST\]** 世界地图作为大型 Overlay
打开，背景世界弱化但保持可感知；本轮不得跳转到与 World 无关的独立页面。

**R-085 \[MUST\]** 底图可以是美术资源，但 Region
节点、道路、状态、Marker、FastTravelPoint 必须数据驱动。

## 12.2 区域地图

**R-086 \[MUST\]** Region Map 重点展示 Map 节点、Gateway
拓扑、Landmark、营地、捷径和阻断状态。

**R-087 \[MUST\]** Region Map 的连接应直接来源于
WorldGraph，不能独立维护一份易冲突的路线数据。

**R-088 \[MUST\]** 隐藏
Map/路线在未发现前不得预留明显空槽、虚线数量或完成度信息泄露其存在。

## 12.3 小地图

**R-089 \[MUST\]** Mini Map 显示当前 Map
的简化几何、玩家、出口、营地/重要地标和当前任务；默认北朝上。

**R-090 \[MUST\]**
小地图不应成为怪物/NPC/宝箱/资源实时雷达；普通对象默认通过世界本身识别。

## 12.4 地图 Context

**R-091 \[MUST\]** 同一地图系统应根据入口 Context
切换表现：导航、任务、图鉴栖息地、快速旅行等，不开发多套重复地图系统。

**R-092 \[MUST\]** 从任务或图鉴打开地图后，Esc
应按栈返回原功能，再回到世界。

# 13. 探索发现、玩家知识与世界状态

**R-093 \[MUST\]** 地点知识至少支持 UNKNOWN → KNOWN → VISITED →
MAPPED（或等价语义）四级；MAPPED 表示主要空间结构已掌握，不表示内容 100%
清空。

**R-094 \[MUST\]** 路线知识与路线通行必须分维度：Knowledge =
UNKNOWN/KNOWN/DISCOVERED；Traversal = OPEN/BLOCKED/LOCKED。

**R-095 \[MUST\]** 知道地点存在不等于知道路线；KNOWN
地点可在地图上模糊显示，但不得自动提供精确导航。

**R-096 \[MUST\]** 第一次真正进入 Map 即标记 VISITED；不得以踩满 Tile
或达到百分比作为访问判定。

**R-097 \[MUST\]** 主要 Landmark 使用
UNKNOWN/DISCOVERED；发现触发可依据视野、距离或实际进入方式配置。

**R-098 \[MUST\]** 营地分 DISCOVERED 与
ACTIVATED；激活后才成为休息、快速旅行、战败返回和自动保存节点。

**R-099 \[MUST\]**
城镇可在第一次进入时自动激活快速旅行，避免无意义额外交互。

**R-100 \[MUST\]**
重要发现自动记录并触发保存，不要求玩家手动“绘制/记录地图”。

**R-101 \[MUST\]** Discovery Event 由 UI、任务、地图、存档等监听；UI
只展示值得注意的发现，普通 Gateway 等可后台记录。

**R-102 \[MUST\]** 已提前 VISITED
的地点在后续“寻找地点”任务中应被识别；但新事件调查不得因去过该地点而自动完成。

# 14. 导航与迷路保护

**R-103 \[MUST\]** 默认采用“软导航”：环境地标、道路、路牌、目标
Region/Map、下一出口；不持续显示全程 GPS 线。

**R-104 \[MUST\]**
主线导航信息可以更明确；普通支线适度弱化；隐藏任务允许依赖文字、方位和环境线索。

**R-105 \[MUST\]**
任务搜索类目标宜使用“区域/搜索范围”而非直接精确坐标，且搜索范围应控制在合理短时内完成。

**R-106 \[MUST\]** 导航路由只能使用玩家已 DISCOVERED 且 OPEN 的
Connection，不得使用未知隐藏捷径泄露秘密。

**R-107 \[MUST\]** 强导航作为玩家主动请求的辅助层，可高亮当前 Map
的“下一 Gateway”，不需要跨多 Map 计算连续地面寻路。

**R-108 \[SHOULD\]**
可选设置提供沉浸/标准/辅助等导航强度；默认推荐“标准”，但本轮核心功能先保证标准模式完整。

**R-109 \[MAY\]**
玩家长时间没有朝当前目标推进且重复绕行时，可提供非阻塞“查看推荐路线”提示，不自动打开地图。

**R-110 \[MUST\]** 路标文字、NPC 地理描述与实际 WorldGraph
方向关系必须一致。

# 15. 地图互动密度与探索节奏

**R-111 \[MUST\]**
地图内容不得通过满屏图标和高频交互点制造密度；应以地标、岔路、遭遇、环境、任务线索形成有呼吸的节奏。

**R-112 \[MUST\]**
主路承载必然内容和稳定推进；支路承载可选价值，如宝箱、稀有遭遇、NPC、捷径、地标、技能书或世界信息。

**R-113 \[MUST\]**
多数支路应有“某种价值”，但不要求每条支路都有物质奖励，避免形成“岔路必有宝箱”的机械认知。

**R-114 \[MUST\]**
宝箱数量宜少而价值更高；固定宝箱与可刷新资源点必须有明显不同的世界表现。

**R-115 \[MUST\]** 野外 NPC
应具有明确存在理由；不得把野外做成密集任务大厅。

**R-116 \[MUST\]** Boss
前应主动降低普通内容密度，通过环境、音乐、普通遭遇减少等建立紧张感。

**R-117 \[MUST\]**
入口、出口、剧情结束和战斗结束后必须有短暂安全缓冲，避免恢复控制权瞬间再次被强制进入遭遇。

**R-118 \[MUST\]**
隐藏内容应有环境线索，如可疑道路、声音、植被、破损围栏等，不得依赖像素级贴墙和攻略式搜索。

# 16. 城镇、营地与野外分工

| **空间**  | **核心角色**              | **典型功能**                                                    |
|-----------|---------------------------|-----------------------------------------------------------------|
| 城镇      | 长期安全基地 / 章节重整   | 主线与重要 NPC、完整商店/仓库、深度培养服务、重要剧情、快速旅行 |
| 营地/前哨 | 旅程安全节点 / 冒险段重置 | 免费恢复、队伍/背包基础管理、存档、快速旅行、有限补给、战败返回 |
| 野外      | 探索与风险空间            | 移动、遭遇、捕捉、任务、道具使用、轻量队伍调整、发现与世界事件  |

**R-119 \[MUST\]**
营地不得复制城镇全部服务；其定位是旅途节点而非“小城镇”。

**R-120 \[MUST\]**
营地基础恢复应免费，不设置露营券、恢复费用或其他惩罚性门槛。

**R-121 \[MUST\]**
野外应允许玩家查看宠物、调整队伍、使用道具、查看地图/任务等，不因“必须回城”人为限制普通管理。

**R-122 \[MUST\]**
只有具有明确设施语义的深度功能才可要求在城镇/特定设施使用。

**R-123 \[MUST\]** 营地可在剧情中从废弃→恢复，作为高价值世界状态变化。

# 17. 野外遭遇与战斗衔接

**R-124 \[MUST\]**
普通遭遇对象应可被玩家看见并允许绕开；不得主要依赖隐藏随机 Trigger
突然强制战斗。

**R-125 \[MUST\]**
遭遇支持玩家主动挑战与敌方主动发现/追击两类入口；追击前必须有可理解的警觉反馈。

**R-126 \[MUST\]** 追击存在最大范围；进入安全区或普通跨 Map
切换后应停止。

**R-127 \[MUST\]** 进入战斗时执行短 Encounter
Transition：锁定输入、镜头聚焦、Explore HUD 弱化、Battle HUD 接管。

**R-128 \[MUST\]**
附近其他普通遭遇对象在战斗期间冻结且不自动加入；群体战斗必须是预先配置的群体遭遇。

**R-129 \[MUST\]**
逃跑成功后玩家与敌人拉开安全距离，敌人短时不再次追击；逃跑不得直接永久清除世界实体。

**R-130 \[MUST\]**
击败或捕捉后对应世界实体应移除/进入刷新逻辑；战斗结束后不得仍原地阻挡玩家。

**R-131 \[MUST\]**
本轮不引入“主动从背后接触获得数值先手”等额外遭遇平衡系统；可保留纯表现差异。

# 18. 战斗覆盖层与结算

**R-132 \[MUST\]**
战斗视觉上应发生在当前地点环境中，但技术上可进入标准化 Battle
Presentation Layer，避免探索地形直接承担完整战斗排布。

**R-133 \[MUST\]** 普通地图通过 Region/Environment Tag
复用战斗环境；Boss、古树核心、祭坛等关键地点可使用专属 Arena。

**R-134 \[MUST\]** Battle Context 期间探索 World Simulation
暂停，其他遭遇对象、NPC、时间与事件冻结。

**R-135 \[MUST\]** Battle Context 隐藏小地图、出口标签、NPC 名称、任务
HUD 等探索交互信息；世界可作为背景但不可交互。

**R-136 \[MUST\]** 战斗前保存
sourceMap、sourcePosition、sourceFacing、sourceCamera、returnContext 与
safeReturnPoint 等必要上下文。

**R-137 \[MUST\]** 胜利/捕捉/逃跑后原则上恢复原
Map、位置、朝向和相机；战败则转移到预先确定的安全返回点。

**R-138 \[MUST\]**
普通战斗结果应集中在一张可快速关闭的结果卡，整合经验、掉落、升级、技能获得等信息，避免多页“下一步”。

**R-139 \[MUST\]**
升级/新技能可提供“查看”入口，但不得强制立即跳入宠物详情或技能替换流程。

**R-140 \[MUST\]** 剧情战斗支持 returnContext=Dialog/Cutscene/Explore
等返回逻辑，不应写死 Battle→Explore。

**R-141 \[MUST\]** Boss 胜利后应回到世界现场展示道路、NPC
或环境变化，再由玩家主动走向新开放区域。

# 19. 冒险耐力、恢复与回城节奏

**R-142 \[MUST\]** 冒险耐力主要由宠物
HP、技能资源、恢复道具、捕捉道具和队伍整体状态形成，不新增独立探索体力条。

**R-143 \[MUST\]** 普通战斗以轻量磨损为主，精英/Boss
才明显提高资源压力；不得让普通探索退化为“打一场喝一次药”。

**R-144 \[MUST\]**
玩家可通过绕开普通遭遇控制消耗；主路不能强制密集连续战斗。

**R-145 \[MUST\]** 营地之间构成一个 Adventure
Segment；抵达营地后可完整恢复并决定继续深入或返回城镇。

**R-146 \[MUST\]**
捕捉道具用尽只限制捕捉，不得禁止继续探索、推进剧情或战斗。

**R-147 \[MUST\]**
若项目存在背包容量，需保持宽松；不得将整理容量变成频繁打断探索的核心玩法。

**R-148 \[MUST\]** Boss 重新挑战成本必须低；首次到 Boss
前应通过营地或可解锁捷径缩短失败后的重复跑图。

**R-149 \[MUST\]**
系统可以提示队伍状态较差或没有恢复道具，但不得强制玩家返回安全点。

**R-150 \[MUST\]**
资源压力必须产生有趣选择；如果某规则只导致玩家无意义原路跑很久，应删除或弱化。

# 20. 任务、剧情与世界变化

**R-151 \[MUST\]**
剧情推进优先表现为世界状态变化：道路、营地、NPC、生态、Boss 阻挡和
Region 状态，而非只更新任务计数。

**R-152 \[MUST\]** 主线优先使用 Region Chapter
结构：进入→发现问题→调查→世界第一次变化→深入→Boss→Region
状态变化→开启后续区域。

**R-153 \[MUST\]**
支线建议区分世界支线、角色支线、探索支线；减少纯重复击杀/采集的任务数量。

**R-154 \[MUST\]** 不得引入每日任务、任务大厅式批量接取或实时运营任务。

**R-155 \[MUST\]**
普通任务接受和步骤更新尽量自然发生，避免每一步都弹“是否接受/点击继续”。

**R-156 \[MUST\]**
提前探索、提前获得关键物品等状态应被后续任务识别，避免要求玩家重复完成已发生的世界事实。

**R-157 \[MUST\]** 核心剧情区域可使用 World Gate
限制流程；普通区域尽量允许玩家提前探索。

**R-158 \[MUST\]** Boss
应承担地图拓扑或世界状态变化，而非仅提供经验与奖励。

**R-159 \[MUST\]**
章节结束应给予呼吸与回访空间，不强制立刻跳转到下一章。

**R-160 \[MUST\]** NPC 对话可根据少量重要 World Flags 变化，重点覆盖
Boss、营地、道路和章节完成状态，不做高成本日程模拟。

**R-161 \[MUST\]**
任务系统应监听世界事实/事件，而不是独占地图状态；例如“修桥任务”监听
bridge_repaired，而非只有点击任务按钮才允许修桥。

# 21. 捷径、快速旅行、战败与存档

**R-162 \[MUST\]**
隐藏路线表示“世界一直存在但玩家尚未发现”；捷径表示“玩家或世界变化后才形成更方便路线”，二者语义必须区分。

**R-163 \[MUST\]** 短距离便利主要由捷径解决，跨较远 Region
的便利由快速旅行解决；强导航不得替代二者。

**R-164 \[MUST\]** 快速旅行默认锚点为城镇和已激活营地；普通 Map
节点不应全部成为传送点。

**R-165 \[MUST\]**
快速旅行可从世界地图直接发起，前提是目标节点已满足激活条件且当前不在
Battle/Cutscene 等禁止状态。

**R-166 \[MUST\]**
战败返回最近已激活安全点或特殊剧情指定安全点；不回滚已经永久发现的地图、捷径、宝箱或重要
World State。

**R-167 \[MUST\]** 战败恢复基本资源不额外收费，降低失败后的重复惩罚。

**R-168 \[MUST\]** 自动保存至少覆盖：Map
关键切换、战斗结束、重要捕捉、任务完成、营地激活、捷径/世界状态变化。

**R-169 \[MUST\]** 普通野外退出游戏应允许恢复到合理的原
Map/坐标；战斗中断按安全快照策略处理，避免要求用户手动存档。

**R-170 \[MUST\]**
不以传统“必须到存档点才能保存”制造焦虑；营地可作为明显的安全/推荐下线节点，但不是唯一存档方式。

# 22. 动态世界：时间、天气、事件与生态

**R-171 \[MUST\]** 动态世界采用“固定地图骨架 + 轻量动态生态 + 低频事件 +
持久剧情变化”，不得开发复杂生态模拟。

**R-172 \[MUST\]**
昼夜可采用有限阶段或日/夜制；使用游戏内时间，不绑定真实世界时间。

**R-173 \[MUST\]** 天气每 Region
只支持少量有意义类型，第一阶段优先影响探索表现与生态，不急于加入大量战斗数值修正。

**R-174 \[MUST\]**
随机事件应低频、短时、可复用模板，不制造实时倒计时或错过焦虑。

**R-175 \[MUST\]**
固定宝箱通常一次性；可再生资源点可刷新，二者不得混淆。

**R-176 \[MUST\]** 动态遭遇对象基于 Spawn
Zone/生态快照组织，避免玩家面前突兀刷新；地图进入、离开或时间变化时可刷新快照。

**R-177 \[MUST\]**
本节动态生态只针对野外遭遇对象/环境，不包含队伍宠物跟随进入探索世界。

# 23. 音画与地图环境表现

**R-178 \[MUST\]** Region 内优先共享主题 BGM，通过
NORMAL/SAFE/DEEP/BOSS/MYSTERY 等 Mood 变体塑造层次，而非每张 Map
完全独立歌曲。

**R-179 \[MUST\]** 普通 Map 切换尽量保持 Region
音乐连续，环境音可根据森林、河流、洞穴、营地等标签渐变。

**R-180 \[MUST\]** Boss
区域通过普通遭遇减少、光照、环境声、音乐与空间变化建立预警，不依赖大面积警告
UI。

**R-181 \[MUST\]**
资源/可交互物体的世界视觉应优先承担识别；只有靠近、Hover
或聚焦时才显示名称与操作提示。

**R-182 \[MUST\]** 交互对象建议遵循 FAR→NEAR→INTERACT→FOCUS
四阶段信息模型。

**R-183 \[MUST\]** 任务目标、普通
NPC、宝箱、资源点不应长期以巨大描边和漂浮标签覆盖画面。

**R-184 \[MUST\]**
可使用少量统一视觉语言区分普通交互、任务、危险、稀有，但色彩/特效不得泛滥。

# 24. 数据一致性与单一真相源

**R-185 \[MUST\]** WorldGraph 必须作为
Region、Map、Gateway、Connection、FastTravelPoint
等空间关系的单一真相源。

**R-186 \[MUST\]** World/Region
Map、导航、任务地点联动、快速旅行不得各自维护冲突的地图连接表。

**R-187 \[MUST\]** World State 分为 Major World State、Dynamic
State、Local State，避免将所有条件组合在单个 Map 分支中。

**R-188 \[MUST\]** Map 最终表现可视为 Base Map + Major World State +
Time/Weather + Dynamic Snapshot + Local State 的合成。

**R-189 \[MUST\]** Player Knowledge 与客观 WorldGraph
分离，保证系统知道隐藏路线存在但玩家导航/地图在未发现前不会泄露。

**R-190 \[MUST\]** Region 探索程度应由 Maps/Landmarks/Connections
等派生，不单独维护容易失真的硬编码百分比。

**R-191 \[MUST\]**
地图连接、发现、捷径、营地等关键状态应具备自动化校验和回归测试能力。

# 25. 桌面端性能、可用性与兼容要求

**R-192 \[MUST\]** 桌面 UI 需覆盖常见 16:9
桌面/笔记本分辨率；保持角色/地图对象可读尺寸，优先改变可视范围而非无限缩小世界。

**R-193 \[MUST\]** 超宽屏可扩大世界视野，但 HUD
应有合理最大内容宽度，避免关键信息贴到过远屏幕边缘。

**R-194 \[MUST\]** Map/Panel/Battle 开关不得造成 World
重新加载、玩家坐标重置或显著闪屏。

**R-195 \[MUST\]** 靠近 Gateway 时应允许预加载目标 Map
资源；普通切换尽量无明显 Loading，超过阈值时才显示轻量 Loading 状态。

**R-196 \[MUST\]** 近期访问 Map
可进行合理缓存，但不能依赖长期保留全部页面/DOM 实例作为世界状态来源。

**R-197 \[MUST\]**
碰撞应宽松且符合视觉：玩家碰撞体可略小于视觉体，装饰物不应普遍卡住移动。

**R-198 \[MUST\]**
所有核心操作必须可通过鼠标+键盘基础行为完成；右键、快捷键等只能增强效率。

**R-199 \[MUST\]** 所有 Blocking Context
都必须正确暂停/恢复世界，不允许打开背包、地图、对话时被后台遭遇攻击。

# 26. 分阶段落地与资源复用约束

推荐先完成一个 Vertical Slice Region，例如“晨曦村 → 森林入口 → 森林南部
→ 猎人营地 → 森林深处 → Boss → 古树核心”，在一个区域内把世界常驻
UI、地图联动、营地、战斗、捷径、发现和世界变化全部跑通，再扩展全世界。

**R-200 \[MUST\]**
后续实施必须先盘点现有页面、地图、配置、资源与代码，区分可直接复用、需适配、需替换、需新增四类。

**R-201 \[MUST\]**
复用已有地图、美术、音频、宠物、技能、道具、组件时必须验证其与新 Map
Contract、WorldGraph 和 UI Context 是否兼容。

**R-202 \[MUST\]**
不得为了保护旧实现而将新需求降级成“旧页面换皮”；必要时允许重构路由、状态管理和地图连接模型。

**R-203 \[MUST\]**
也不得为了“彻底重构”无理由推翻可复用且满足需求的成熟模块；优先最小必要改造。

**R-204 \[MUST\]**
技术改造应尽量保持既有宠物、技能、道具、难度、自动战斗等业务规则可复用，除非其行为直接与本需求冲突。

**R-205 \[MUST\]**
每阶段完成后必须对需求覆盖、回归风险、文档一致性和遗留项进行核对，不得只以“代码能运行”作为完成标准。

# 27. 验收标准

## 27.1 体验级验收

- 玩家从探索打开队伍、背包、任务、地图、商店或对话，关闭后仍处于原 World
  位置与上下文，不发生不必要的页面跳转。

- 玩家从一个 Map 出口进入相邻
  Map，方向、入口、HUD、任务与音频连续，能够理解“刚从哪里来、下一步去哪”。

- 玩家能仅依赖地标、道路、路牌、区域地图和下一出口完成主要导航，不需要持续
  GPS 线。

- 战斗从地图遭遇自然进入，结束后胜利/捕捉/逃跑恢复原地，战败返回安全点；世界状态正确。

- Boss
  胜利会在世界现场产生可见变化（道路、阻挡、NPC、区域状态等），而非只有奖励数字。

- 首次探索某 Region
  后，玩家能说出至少几个主要地点、营地、主路线和重要地标之间的关系。

- 旧 Map 回访时可因快捷路线、World
  State、任务或生态出现新意义，不是简单重复跑图。

## 27.2 数据与逻辑验收

- 所有非单向 Gateway 均成对，目标 Gateway 存在且返回关系正确。

- 从世界起点可达的主线 Map 均可达；没有因错误连接导致的永久不可达节点。

- 隐藏路线在 Player Knowledge 未发现前不会被 World/Region
  Map、任务导航和路线预览泄露。

- BLOCKED/LOCKED Connection 在状态解除后，地图、导航和实际通行同步更新。

- SafePoint 发现、激活、快速旅行、战败返回与自动保存使用一致状态。

- 地图、区域图、导航、任务地点与快速旅行读取同一 WorldGraph，不出现 A
  系统说通向 B、B 系统显示通向 C 的冲突。

- 提前 VISITED
  的地点能被后续地点型任务识别；事件型任务仍要求对应新事件完成。

## 27.3 UI/Input 验收

- Blocking Panel 打开时 WASD
  不移动角色；关闭后角色不会因旧按键状态继续滑动。

- 浏览器失焦或文本输入时快捷键不会错误驱动世界。

- Esc 按 Context Stack 正确逐层返回。

- 普通 Toast/Tooltip 不阻塞移动；Dialog/Map/Shop/Pet Detail/Battle
  正确暂停世界。

- 中央探索视野长期保持干净，不出现大量常驻标签、血条、任务图标和资源图标。

# 28. 明确延期 / 非本轮范围

- 手机版 UI、触控适配、虚拟摇杆与移动端导航。

- 队伍宠物跟随玩家在世界地图中展示。

- 真正无缝开放世界 Streaming 与跨 Map 实时敌人追击。

- 复杂生态食物链、NPC 全天候日程模拟。

- 饥饿、体力、温度、装备耐久等生存系统。

- 每日任务、运营活动、实时限时事件与 FOMO 机制。

- 自动寻路/自动跑图作为默认主体验。

- 为每个商店制作独立室内场景、为每张 Map
  制作独立战斗背景等高成本低复用内容。

# 附录 A. 推荐状态模型

> LocationKnowledge:  
> UNKNOWN → KNOWN → VISITED → MAPPED  
>   
> ConnectionKnowledge:  
> UNKNOWN → KNOWN → DISCOVERED  
>   
> ConnectionTraversal:  
> OPEN \| BLOCKED \| LOCKED  
>   
> SafePoint:  
> UNKNOWN → DISCOVERED → ACTIVATED  
>   
> Landmark:  
> UNKNOWN → DISCOVERED

注意：以上是需求层语义，不强制具体代码枚举命名。技术方案可根据现有架构映射，但最终行为必须等价。

# 附录 B. AI 变更与规划工作要求摘要

- 先读取现有需求、技术、规划、README/目录说明、AGENTS
  或同类规则，以及相关前后端代码、地图/配置和资源清单。

- 先生成“现状盘点 + 差距分析 + 影响范围 + 资源复用判断 +
  风险”文档，再更新需求/技术/规划，不得直接跳到大规模编码。

- 将本需求视为桌面版新基线；若旧文档冲突，明确标记并调整，不得默默保留冲突行为。

- 按 Vertical Slice 优先跑通一个 Region
  全链路，再扩展世界，避免先批量生产几十张地图。

- 复用资源时逐项验证满足需求；不满足则改造/替换，以完成需求为第一前提。

- 对 WorldGraph/Gateway/Discovery/SafePoint/Shortcut/Context Stack
  建立自动化检查与验收。

- 开发完成后更新文档并输出需求覆盖表、未完成项、技术债和后续阶段建议。
