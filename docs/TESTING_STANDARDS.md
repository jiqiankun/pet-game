# 测试规约

**适用项目：** 宠物精灵游戏第一阶段  
**依据：** 《宠物精灵游戏第一阶段技术方案说明 V1.0》《宠物精灵游戏分阶段开发规划 V1.0》

---

## 1. 测试原则

- **不追求高覆盖率**，聚焦核心游戏规则的可靠性。
- Phaser 表现以人工测试为主，不为技能动画建立复杂自动化视觉测试。
- 测试重点集中在 BattleEngine、捕捉计算、成长系统、Boss 系统、放生奖励等核心规则。
- 每个阶段的实现过程中，核心规则必须具备**可验证的测试**（单元或集成）。

---

## 2. 后端单元测试重点

### 2.1 BattleEngine（最高优先级）

必须测试的规则：

| 规则 | 验证要点 |
|---|---|
| 行动顺序 | 按速度从高到低排列；速度相同随机决定；每回合重算 |
| 属性克制 | 克制 ×1.50、普通 ×1.00、被克制 ×0.75 |
| 本属性加成 | 同属性技能 ×1.20；跨属性不获得加成 |
| 暴击 | 基础 5%；倍率 1.4～2.0 均匀随机；治疗不暴击 |
| 命中 | 技能命中率生效；致盲等状态影响命中；正常命中最低 1 点伤害 |
| 技能冷却 | 每只宠物独立计算；冷却回合内不可使用 |
| Buff/Debuff | 正确叠加/覆盖/到期清除 |
| 换宠 | 主动换宠消耗行动；新宠物立即进场承受后续攻击 |
| 补位 | 倒下后候补补位不消耗下一回合行动 |
| 被动技能 | 触发时机正确（登场/退场/受击/攻击/暴击/击败/倒下/回合开始/结束） |
| 群体技能 | 正确作用于全体目标；原则上不受嘲讽影响 |
| 嘲讽与援护 | 嘲讽影响单体技能目标；援护替队友承担部分伤害 |
| 失去战斗能力 | HP ≤ 0 正确标记；全部 6 只倒下则战斗失败 |

### 2.2 CaptureCalculator

| 规则 | 验证要点 |
|---|---|
| HP 系数 | HP 越低捕获率越高 |
| 异常系数 | 异常状态提升捕获率 |
| 捕捉球倍率 | 普通/高级/特级三档倍率正确 |
| 精英倍率 | 精英个体 ×0.6（配置化） |
| 边界 | 捕获率不低于 0%、不高于 100% |
| 多宠物遭遇 | 捕捉成功该宠物退出敌方队伍；其余继续战斗 |

### 2.3 Pet Growth（成长系统）

| 规则 | 验证要点 |
|---|---|
| 升级 | 五种升级操作（升1/升5/升到指定/升到上限/自定义投入）结果正确 |
| 自由属性点 | 每级 3 点 + 稀有度每 10 级额外（0/2/4/6） |
| 属性点转换 | 生命+5/力量+1/灵力+1/防御+1/抗性+1/速度+1消耗2点 |
| 洗点 | 点数完整返还；免费 |
| 等级上限 | Lv.50 不可超出 |
| 升级预览 | 预览结果与实际一致 |
| 经验不足 | 阻止分配并明确提示 |

### 2.4 Boss 系统

| 规则 | 验证要点 |
|---|---|
| 掉落情报 | 3/6/10 次击败逐级解锁；提前获得立即解锁 |
| 幸运值累计 | 按难度配置增加（如 +4/+7/+10）；不同难度共享 |
| 幸运值溢出 | 超过 100 保留余数（如 245 → 兑换后剩余 45） |
| 多次兑换 | 每 100 点兑换一次，不封顶；只能选该 Boss 已公开掉落 |
| 难度解锁 | 普通首通 → 困难；困难首通 → 噩梦 |
| 自动挑战 | 失败自动停止；每场真实执行；不是扫荡 |
| 自动解锁 | 未手动击败过的敌人/难度不允许自动 |

### 2.5 放生系统

| 规则 | 验证要点 |
|---|---|
| 礼物价值 | 普通/稀有/珍稀/传说基础值 20/60/150/400 |
| 等级系数 | 1 + 捕获等级 × 1%（上限 ×1.5） |
| 培养系数 | 范围 1.0～1.5，上限不超过 50% |
| 底线验证 | 总价值 ≥ 四舍五入后的应得点数 |
| 批量放生 | 自动排除锁定/收藏/在队宠物 |
| 锁定保护 | 锁定宠物禁止放生 |

### 2.6 配置校验

| 规则 | 验证要点 |
|---|---|
| ID 重复 | 同类型配置出现重复 ID 时启动失败 |
| 引用不存在 | 技能/宠物/Boss 引用不存在的配置时启动失败 |
| 非法概率 | 概率值超出 0～1 范围时启动失败 |
| 非法倍率 | 倍率为负数或异常大值时启动失败 |
| 属性不存在 | 宠物属性不在 9 属性中时启动失败 |

## 3. 前端测试重点

以下前端功能以组件/页面级验证为主：

| 功能 | 验证要点 |
|---|---|
| 加点计算展示 | 属性变化预览与实际结果一致 |
| 经验升级预览 | 所需经验、升级后等级、属性变化显示正确 |
| 捕获概率显示 | 使用捕捉道具前显示具体成功率；宠物状态变化后实时更新 |
| 仓库筛选排序 | 全部筛选条件与排序规则正确生效 |
| 队伍编辑 | 首发/候补/5 套预设/拖拽调整正确 |
| Boss 幸运值 | 显示累计值、兑换进度、掉落解锁进度 |
| 战斗界面 | HP、属性、Buff/Debuff、技能冷却、行动顺序条正确显示 |
| 响应式 | PC/平板/手机尺寸下核心操作全部可用 |

## 4. 集成测试

关键事务流程需要端到端验证：

- **战斗结算**：战斗结束 → HP/经验/金币/掉落/图鉴/统计 全部正确更新，同一事务内完成。
- **捕获流程**：捕捉成功 → 创建宠物 + 扣捕捉球 + 更新图鉴 + 更新统计，同一事务内完成。
- **放生流程**：放生 → 计算礼物 + 发礼物 + 删除宠物 + 更新统计，同一事务内完成。
- **幸运兑换**：兑换 → 校验幸运值 + 扣幸运值 + 发放奖励，同一事务内完成。
- **存档导入导出**：导出 → 重置 → 导入 → 数据正确恢复；导入失败时原存档回滚。
- **重启恢复**：所有持久化操作后重启服务，数据完整保留。

## 5. 随机种子测试

- 固定随机种子后，完整战斗流程（行动顺序、暴击、命中、掉落）可完全复现。
- 固定种子后，捕捉结果、资质生成、放生礼物可完全复现。
- 用于 Bug 复现和数值平衡调试。

---

## 6. 阶段验收规则

### 6.1 验收流程

每个开发阶段完成后：

1. 逐条对照该阶段「完成标准」验证。
2. 逐条对照该阶段「核心业务规则」验证。
3. 汇报：已完成项、验证结果（通过/未通过/待确认）、遗留问题、风险。
4. **阶段验收通过前，不开启下一阶段开发。**

### 6.2 验收自查清单

- 所有核心规则具备可验证的测试（单元或集成）。
- 不存在需要手工复制文件才能完成的发布流程。
- 数据在重启后完整保留。
- 不出现脏数据（经验池重复扣减、结算部分成功等）。
- 不允许在 Phaser 场景中出现业务数据操作。

---

## 7. 回归测试规则

修改以下模块时，必须重新验证关联测试：

| 修改范围 | 必须回归验证 |
|---|---|
| BattleEngine 核心代码 | 全部 BattleEngine 测试用例 |
| 捕捉公式或参数 | 全部 CaptureCalculator 测试 |
| 升级/加点/成长逻辑 | 全部 Pet Growth 测试 |
| Boss 相关逻辑 | 全部 Boss 系统测试 |
| 放生奖励逻辑 | 全部放生系统测试 |
| 配置体系 | 配置校验测试 + 受影响模块 |
| 统一随机工具 | 所有依赖随机的测试 |

---

## 8. 测试执行时机

- **编码过程中**：每完成一个核心规则，立即编写对应测试。
- **阶段验收前**：运行全部相关测试，确保无回归。
- **提交代码前**：确认所有现有测试通过。
- **AI 辅助开发时**：每个开发任务结束时，汇报测试验证结果。
