# 被动技能体系扩充与技能书整合方案

> 状态：待评审
> 关联阶段：阶段 14（内容补齐 / 数值平衡）
> 原则：**固有被动决定「它是谁」；技能书被动决定「你想把它培养成什么风格」。**

---

## 1. 背景与目标

项目已完成被动技能框架（阶段 3）与技能书体系（阶段 10），并在阶段 14 补齐了 10 种被动技能书。
但当前实现存在结构性缺陷：

1. **技能书被动与固有被动混为一池**：所有学习过的技能书被动在战斗中永久自动生效，无装备限制。
2. **无效果组与叠加规则**：同名/同效果被动可能重复叠加，造成数值膨胀。
3. **固有被动数量偏少**：当前每宠仅 2~3 个固有被动，特色不足。

本次目标是在**不推翻此前后续被动扩充方向**的基础上，做结构性修正：

- 明确 **固有被动** 与 **技能书被动** 两大来源及其职责边界。
- 技能书被动引入 **独立生效限制（2 槽）**，实现「已学习 ≠ 当前生效」。
- 引入 **效果组（effectGroup）+ 叠加规则（stackRule）**，防止同名/同组重复与数值膨胀。
- 现有 10 种被动技能书全部盘点、调整；**不新增大量技能书**。

### 2.2 现有生效机制（代码事实）

- **固有被动**：`pets.yml` 的 `species.passives`（`{passiveId, unlockLevel}`），
  等级 `>= unlockLevel` 即在 `BattleService.buildPlayerUnit` 自动加入 `unit.passives`，无装备槽。
- **技能书被动**：`learnSkillBook` 写入 `player_pet_skill`（`sourceType=SKILL_BOOK`，`slot=null`），

- **主动技能书**：学习上限 `BOOK_SKILL_LEARN_LIMIT=10`、装备槽 `BOOK_SKILL_EQUIP_SLOTS=2`（槽位 5~6），
  已有 `equipBookSkill` / `unequipBookSkill` 复用价值高。
- **被动管理**：`PassiveManager` 按 `trigger + effectType` 配置驱动，无 effectGroup / stackRule。

### 2.3 现有被动效果类型（`PassiveSkillConfig.effectType` 支持集）

`SURVIVE_LETHAL / APPLY_STATUS_ALLY_ALL / APPLY_STATUS_SELF / DAMAGE_ENEMY_RANDOM / HEAL_SELF / REDUCE_PHYSICAL_DAMAGE` 等。

## 3. 被动两大来源划分

### 3.1 固有被动（INNATE / LEVEL_UP / EVOLUTION）

- **来源**：出生自带、升级自动获得、成长/进化获得、宠物特有/准专属。
- **职责**：决定「这只宠物是谁」—— 种族特色、战斗定位、元素特色、状态联动、队伍作用、专属玩法。
- **生效**：战斗中全部自动生效，不占主动技能槽、不需要装备、不设携带数。
- **数量控制**：单宠 3~5 个，按等级体系分布（Lv1 天生 1、中前期 1、中期 1、中后期 1、部分多 1 特色）。

### 3.2 技能书被动（SKILL_BOOK）

- **来源**：被动技能书后天学习。
- **职责**：决定「玩家如何培养」—— Build 调整、属性补强、战术微调、弱点补偿、定位强化。
- **关键规则（本次核心修改）**：**已学习 ≠ 当前生效**。每宠最多同时**启用 2 个**技能书被动。
- **禁止**：技能书成为宠物核心身份来源。

### 3.3 职责隔离红线

以下能力**原则上只保留给固有被动**，不作为通用技能书：
复活、击杀额外行动、极强反击、特殊换宠、专属元素循环、形态变化、核心状态机制、Boss 级能力、关键致死保护、宠物招牌机制。

## 4. 被动池规模

- **整个被动体系**：维持约 60~90 个机制（含固有 + 技能书）。
- **技能书数量**：当前 10 本优先保留并优化，**本阶段不掉加几十本**。
- **固有被动**：以现有 27 宠为基础，每宠补足至 3~5 个（当前多数仅 2~3 个）。

## 6. 技能书被动槽设计（核心）

### 6.1 规则

- 每宠最多同时**启用 2 个技能书被动**（`BOOK_PASSIVE_EQUIP_SLOTS = 2`）。
- 学习数量与生效数量分离：技能书学习沿用现有机制（主动仍 10 上限；被动学习数量沿用现有——被动无硬上限但受槽位约束实际参与有限）。
- 玩家可在战斗外切换启用/卸下/替换。

### 6.2 命名与数据

沿用 `player_pet_skill.slot` 区分装备状态：
- 主动技能书：`slot 5~6`（沿用 `BOOK_SLOT_START=5`）。
- 被动技能书：**复用同一 `slot` 表达「启用槽」**，规定被动技能书启用槽为 `slot=7~8`（避开主动 1~4 与主动技能书 5~6）。
- `slot=null` = 已学习但未启用。

### 6.3 为什么 2 槽

1 槽自由度低；2 槽能形成明显搭配、不易带满强技、不显著增加战斗复杂度，契合轻量单机定位。不设计 5/6/无限槽。

## 7. 10 种技能书盘点与调整

逐一判定（是否通用、是否过强、是否抹平特色、是否适合所有宠物、是否需要学习条件、是否与固有重复、是否数值叠加、是否触发循环、是否更适合转固有）：

| 技能书 | 定位 | 通用性 | 判定 | 调整动作 |
|---|---|---|---|---|
| 先锋 | 全队开场攻击 | 通用 | **过强**（全队光环，易成必选） | 保留但**弱化**：改为仅自身攻击（或降为 1 回合仅加速），避免全队光环成为所有队伍必选 |
| 铁壁光环 | 全队开场防御 | 通用 | 类同先锋 | 同上，二选一方向调整，避免「先锋+铁壁」双光环无脑全带 |
| 登场蓄力 | 自身开场攻击 | 通用 | 合理通用强化 | 保留；归属辅助强化类 |
| 稳固 | 物理减伤 | 通用抗性 | 合理 | 保留；抗性/生存类 |
| 回气 | 回合回血 | 通用 | 合理 | 保留；生存类 |
| 乘胜追击 | 击杀加攻 | 通用 | 偏输出向，可作 Build | 保留；归属攻击触发型，建议加「仅输出定位」或保持通用但数值温和 |
| 烬爆 | 倒下火伤 | 通用 | **接近招牌/死亡机制** | 弱化倾向：保留但收敛为「倒下对小范围造成少量火伤」，数值调低；不升级为复活类 |
| 荆棘气场 | 受击反伤 | 通用 | **反伤易成攻坚无脑解** | 保留但加 `oncePerTurn`（已有）并收敛数值；标注为「反伤向 Build」技能书而非万金油 |
| 殊死 | 首次致命保1HP | 通用 | **接近无条件致死保护，偏招牌** | **降级为受限技能书**：增加限制（如坦克/防御定位 或 高稀有度），且数值按「唯一保命手段」定位收敛；备选：转某宠固有 |
| 复仇 | 队友倒下加攻 | 通用 | 偏阵容向 | 保留；归属队伍协同类，作为 Build 调整 |

**调整原则**：不做大规模删除；优先「收敛数值 / 加限制 / 明确方向」；对接近招牌机制的（殊死、烬爆）明确降级或限制，防止通用技能书抹平宠物特色。

> 注：实际数值/限制的最终值需结合战斗调试工具实测校准（阶段 14 总验收）。

## 8. 效果组与叠加规则

### 8.1 效果组（effectGroup）

`PassiveSkillConfig` 新增 `effectGroup` 字段，用于归一化「不同名字但效果相近」的被动：

```
HP_BONUS / ATTACK_BONUS / DEFENSE_BONUS / SPEED_BONUS / RESIST_BONUS /
DAMAGE_REDUCTION / STATUS_RESIST / HEAL_BONUS / SHIELD_BONUS / ON_KILL_ATK / ...
```

### 8.2 叠加规则（stackRule）

```
UNIQUE         同组只允许一个（核心/强机制）
HIGHEST_ONLY   同组只取最高效果（同名被动、属性类）
ADDITIVE       允许加算（普通属性强化，配合总上限）
LIMITED        允许叠加但存在上限（maxStack）
```

**默认策略**：
- 普通属性强化 → `ADDITIVE` + `maxStack` 上限。
- 强机制 → `UNIQUE`。
- 同名技能书/固有 → `HIGHEST_ONLY`。

### 8.3 同名/同组去重

- 同名被动：只生效一次（`HIGHEST_ONLY`）。
- 固有「迅捷」+ 技能书「迅捷」：不双倍，取更高效果。
- 不同名但同 `effectGroup`：按 `stackRule` 处理。

### 8.4 实现位置

在 `BattleUnit` 装配被动时（`buildPlayerUnit` + 敌军构建）与 `PassiveManager` 应用前，对 `unit.passives` 做一次**效果组归一化/去重**。
推荐用一个轻量 `PassiveEffectResolver` 处理，避免在 `PassiveManager` 每次触发重复计算。

## 9. 数据结构影响

### 9.1 `PlayerPetSkillEntity`（复用，不新增表）

- 被动技能书启用状态沿用 `slot`（7~8 表示启用槽），无需新增字段。
- 无需新增 `equipped` 布尔字段 —— 避免两套互相矛盾的状态标记。

### 9.2 `PassiveSkillConfig`

新增字段：

```java
private String sourceType;    // INNATE / LEVEL_UP / EVOLUTION / SKILL_BOOK（概念层 + 配置标注）
private String effectGroup;   // HP_BONUS / ATTACK_BONUS / ...
private String stackRule;     // UNIQUE / HIGHEST_ONLY / ADDITIVE / LIMITED（默认 HIGHEST_ONLY）
private Integer maxStack;     // LIMITED 时上限
private Integer priority;     // 同组冲突时高优先级胜出
```

> 说明：`sourceType` 在配置层用于标注「本被动默认归属」，实际生效来源仍由 `species.passives`（固有）与 `player_pet_skill`（技能书）决定，二者不冲突。

### 9.3 定义层共享

底层 modifier（如 SPEED_UP）可被某宠固有与某技能书共同复用，但**概念来源必须明确**：
- 固有被动 = `species.passives`。
- 技能书被动 = `player_pet_skill(sourceType=SKILL_BOOK)`。
禁止把宠物机制复制成技能书。

## 12. AI 影响

自动战斗 AI（`AutoBattleDecisionProvider`）需感知当前启用的技能书被动，但**避免 per-book 硬编码 if**。

- 采用 **passive tag / effectGroup / combat modifier** 语义：
  - 启发杀伤类（ON_KILL、低血增伤）→ 提高低 HP 目标价值。
  - 治疗强化类 → 适度提高治疗技能价值。
  - 换宠强化类 → 适当时机提高换宠收益。
- 引擎侧把「当前生效被动集合」连同其 effectGroup/tag 暴露给决策器，决策器读取语义标签即可。

---

## 13. Boss 兼容

技能书不能成为 Boss 机制漏洞。重点回归：
致死保护、反伤、百分比伤害、复活、控制、护盾、回血、换宠、额外行动。

- Boss 可拥有抗性/机制修正，但**不完全禁用技能书**。
- 针对 8、9 节去重与防循环，确保：
  - 反伤不触发反伤；
  - 被动伤害不无限触发攻击被动；
  - 治疗被动不无限触发治疗被动；
  - 换宠被动不造成换宠循环；
  - 额外行动不造成无限行动。
- 复用 `PassiveManager` 既有防递归（`MAX_PASSIVE_DEPTH` + oncePerTurn/oncePerAction/maxTriggerPerBattle）。

## 15. 测试方案

新增/调整测试：

### 固有被动
- 天生被动正确生效；升级正确获得；自动生效；不占主动技能槽。

### 技能书学习
- 可正确学习；学习状态持久化；重复学习拒绝。

### 技能书装备（被动）
- 最多启用 2 个；第 3 个无法直接启用；可正常替换；卸下后立即失效；固有被动不受影响。

### 重复规则
- 固有「迅捷」+ 技能书「迅捷」不双倍生效（HIGHEST_ONLY）。

### 效果组
- 同组技能按设定规则处理（ADDITIVE + 上限 / HIGHEST_ONLY / UNIQUE）。

### 战斗
- 开场、攻击、受击、DOT、反伤、回复、换宠、状态、击杀、Boss 各场景。

### AI
- 确认 AI 能识别当前启用技能书被动。

## 16. 风险分析

| 风险 | 影响 | 缓解 |
|---|---|---|
| 被动叠加导致数值膨胀 | 平衡破坏 | effectGroup + stackRule + maxStack |
| 技能书趋同（所有宠物同 2 本） | 失去 Build 意义 | 横向平衡检查、受限技能书、弱化通用强技 |
| 通用技能书复制招牌机制 | 宠物特色被冲淡 | 职责隔离红线（§3.3） |
| 战斗复杂度上升 | 反轻量 | 2 槽上限 + 配置驱动 + 复用防递归 |
| 旧数据兼容 | 数据异常 | 一次性兜底（§10） |
| 实现范围失控 | 违背阶段约束 | 不新增大量技能书、不做技能书等级/随机词条 |

## 18. 验收标准（对照需求 §48）

1. 被动明确分固有 / 技能书两大来源。
2. 27 宠固有特色不被技能书冲淡。
3. 固有被动全部自动生效。
4. 每宠约 3~5 个固有被动。
5. 每宠至少 1 个核心特色被动。

10. 默认最多启用 2 个技能书被动。
11. 技能书槽不占主动技能槽。

13. 同类效果有清晰叠加规则。
14. 无明显数值膨胀。
15. 无无限触发。
16. Boss 兼容。
17. AI 合理利用。
18. UI 清楚显示固有/技能书被动。
19. 玩家方便切换技能书 Build。
20. 不增加大型天赋树等复杂系统。
