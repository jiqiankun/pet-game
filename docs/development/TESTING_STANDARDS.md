# 测试规约

**适用项目：** 宠物精灵游戏第一阶段 + 桌面版世界/UI 重构
**依据：** 《宠物精灵_桌面版世界与UI重构_完整需求文档_V1.0》《宠物精灵_需求变更与桌面版世界UI重构_详细任务规划.md》《宠物精灵游戏第一阶段技术方案说明 V1.0》

---

## 1. 测试原则

- **不追求高覆盖率**，聚焦核心游戏规则的可靠性。
- Phaser 表现以人工测试为主，不为技能动画建立复杂自动化视觉测试。
- 测试重点集中在 BattleEngine、捕捉计算、成长系统、Boss 系统、放生奖励等核心规则。
- 每个阶段的实现过程中，核心规则必须具备**可验证的测试**（单元或集成）。

## 2. 后端单元测试重点

### 2.1 BattleEngine（最高优先级）

必须测试的规则：

| 规则 | 验证要点 |
|---|---|
| 行动顺序 | 按速度从高到低排列；速度相同随机决定；每回合重算 |
| 属性克制 | 克制 ×1.50、普通 ×1.00、被克制 ×0.75 |
| 本属性加成 | 同属性技能 ×1.20；跨属性不获得加成 |
| 暴击 | 基础 5%；倍率 1.4～2.0 均匀随机；治疗不暴击 |
| 命中 | 技能命中率生效；致盲等状态影响命中；正常命中最低 1 点伤害 |
| 技能冷却 | 每只宠物独立计算；冷却回合内不可使用 |
| Buff/Debuff | 正确叠加/覆盖/到期清除 |
| 换宠 | 主动换宠消耗行动；新宠物立即进场承受后续攻击 |
| 补位 | 倒下后候补补位不消耗下一回合行动 |
| 被动技能 | 触发时机正确（登场/退场/受击/攻击/暴击/击败/倒下/回合开始/结束） |
| 群体技能 | 正确作用于全体目标；原则上不受嘲讽影响 |
| 嘲讽与援护 | 嘲讽影响单体技能目标；援护替队友承担部分伤害 |
| 失去战斗能力 | HP ≤ 0 正确标记；全部 6 只倒下则战斗失败 |

### 2.4 Boss 系统

| 规则 | 验证要点 |
|---|---|
| 掉落情报 | 3/6/10 次击败逐级解锁；提前获得立即解锁 |
| 幸运值累计 | 按难度配置增加（如 +4/+7/+10）；不同难度共享 |
| 幸运值溢出 | 超过 100 保留余数（如 245 → 兑换后剩余 45） |
| 多次兑换 | 每 100 点兑换一次，不封顶；只能选该 Boss 已公开掉落 |
| 难度解锁 | 普通首通 → 困难；困难首通 → 噩梦 |
| 自动挑战 | 失败自动停止；每场真实执行；不是扫荡 |
| 自动解锁 | 未手动击败过的敌人/难度不允许自动 |
| 控制抗性 | Boss 0.6 / 精英 0.8 / 普通 1.0；施加控制类状态时先乘抗性再乘衰减 |
| 连续控制衰减 | 第 1/2/3 次施加控制成功率 ×1.0/0.7/0.4；连续 2 回合未受控归零 |
| 阶段触发 | HP 低于阈值触发 ADD_SKILL/ADD_SHIELD/BUFF_SELF；每触发器仅激活一次；不重复触发 |
| 多阶段 | 不同 HP 阈值触发不同效果（如 50% + 25%） |
| Boss 不可捕捉 | uncapturable 标记生效，前端禁用捕捉/逃跑按钮 |

## 4. 集成测试

关键事务流程需要端到端验证：

- **战斗结算**：战斗结束 → HP/经验/金币/掉落/图鉴/统计 全部正确更新，同一事务内完成。
- **捕获流程**：捕捉成功 → 创建宠物 + 扣捕捉球 + 更新图鉴 + 更新统计，同一事务内完成。
- **放生流程**：放生 → 计算礼物 + 发礼物 + 删除宠物 + 更新统计，同一事务内完成。
- **幸运兑换**：兑换 → 校验幸运值 + 扣幸运值 + 发放奖励，同一事务内完成。
- **存档导入导出**：导出 → 重置 → 导入 → 数据正确恢复；导入失败时原存档回滚。
- **重启恢复**：所有持久化操作后重启服务，数据完整保留。

## 6. 阶段验收规则

### 6.1 验收流程

每个开发阶段完成后：

1. 逐条对照该阶段「完成标准」验证。
2. 逐条对照该阶段「核心业务规则」验证。
3. 汇报：已完成项、验证结果（通过/未通过/待确认）、遗留问题、风险。
