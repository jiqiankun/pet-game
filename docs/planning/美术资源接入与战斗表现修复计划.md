# 美术资源接入与战斗表现修复计划

**状态：** 待实施  
**制定日期：** 2026-08-15  
**适用范围：** 第一阶段阶段 14 的总验收回归修复，不新增玩法或基础设施。

## 1. 目标与边界

本计划解决已完成资源审查发现的「资源已生成但未在关键页面呈现」问题，使战斗、队伍与培养等核心操作可以直接识别宠物和 Boss。

- Vue 只负责表现；不改变 BattleEngine、战斗公式、掉落或存档结构。
- 战斗特效仍严格由后端 `BattleEvent` 驱动，前端不推导任何战斗结果。
- 只复用 `frontend/public/assets` 中已有资源；仅补齐 10 张已配置但缺失的技能书图标。
- 成就、统计、设置、存档备份、开发者工具等数据页不强制增加装饰性图片。

## 2. 审查基线

| 项目 | 现状 | 处理结论 |
| --- | --- | --- |
| 宠物资源 | 27 张立绘、81 张图标齐全 | 接入战斗、首页、队伍、新游戏、宠物详情 |
| Boss 资源 | 8 张立绘齐全 | 接入 Boss 核心单位的战斗卡片 |
| 战斗背景与特效 | 6 张背景、31 张特效精灵图均存在 | 修正播放帧终点并延长可感知时长 |
| 道具资源 | 45 个配置道具中 10 个技能书图标缺失 | 补齐对应文件，避免背包与商店图片 404 |

## 3. 实施任务

### P0：战斗单位美术与特效

| ID | 任务 | 最小改动 | 验收标准 |
| --- | --- | --- | --- |
| ART-01 | 补齐战斗展示标识 | 在 `BattleUnit` 与 `UnitSnapshot` 增加可展示的 `artType`、`artId`；宠物使用种族 ID，Boss 核心使用 Boss ID，测试敌人没有资源时返回空值 | 战斗快照可无歧义区分宠物、Boss 与无立绘测试单位；不影响既有字段和战斗计算 |
| ART-02 | 在战斗卡片渲染立绘 | `BattleView` 根据 `artType/artId` 显示宠物或 Boss 立绘；无资源时保留现有文字卡片，不请求不存在路径 | 玩家宠、野生宠、Boss 核心和 Boss 支援单位均可正确显示；昵称不影响图片选择 |
| ART-03 | 修正特效播放 | 保留当前「一次快照播放一个最高优先级特效」策略；将四帧精灵图终点从 `-512px` 改为 `-384px`，基础播放时长由 333ms 调整为约 600ms，并随 1×/2×/3× 缩放 | 火、水、控制、治疗、护盾、捕捉、Boss 阶段切换均能看见完整四帧；最后一帧不闪空白 |

**实现约束：** 不建立特效队列、时间轴或 Phaser `BattleScene`。现有事件优先级足以满足第一阶段表现需求；后续只有确实需要多段连续演出时才考虑队列。

### P1：核心宠物页面复用现有资源

| ID | 页面 | 最小呈现方式 | 验收标准 |
| --- | --- | --- | --- |
| ART-05 | 首页 | 当前队伍条目显示 64px 宠物图标 | 宠物名称、等级、HP 与图标对应同一 `speciesId` |
| ART-06 | 队伍 | 六个编队槽位显示 64px 宠物图标 | 拖拽、下拉选择、清空和保存行为不回归 |
| ART-07 | 新游戏 | 初始宠物三选一卡片显示宠物立绘或 128px 图标 | 三只候选宠物均与 API 返回的 `speciesId` 对应 |
| ART-08 | 宠物详情 | 详情首屏显示选中宠物立绘 | 切换宠物后立绘、名称、属性和技能信息同步更新 |

不纳入本计划：为成就、统计、设置、备份或开发者工具新增装饰图；这些页面以信息密度和可用性为主。

## 4. 实施顺序

1. 完成 ART-01，先建立战斗快照的展示标识契约，并补充 DTO 映射测试。
2. 完成 ART-02 与 ART-03，进行玩家宠、野生宠、Boss 和测试战斗的手动表现验证。
3. 完成 ART-04，执行配置道具 ID 与图标文件的一致性检查。
4. 完成 ART-05 至 ART-08，只复用现有资源路径与页面数据，不增加接口。
5. 运行构建与回归检查，更新状态文档中的美术验收结论。

## 5. 验收清单

### 自动验证

- 后端：`UnitSnapshot` 映射测试覆盖宠物、Boss 核心、Boss 支援与无资源测试敌人。
- 前端：`vue-tsc -b` 与 `vite build` 通过。
- 资源一致性：27 个宠物种族的立绘与 64px 图标、8 个 Boss 立绘、45 个道具图标均存在；所有页面生成的资源路径必须对应真实文件。

### 手动验证

- 从地图遭遇进入野生战斗，己方和敌方宠物立绘正确显示；捕捉、伤害、治疗和控制特效完整可见。
- 从 Boss 页开始各难度战斗，Boss 核心使用 Boss 立绘、支援位使用宠物立绘，阶段切换特效正确播放。
- 在首页、队伍、新游戏与宠物详情页切换不同种族，图片与文字信息保持一致。
- 在背包和商店查看全部 10 本被动技能书，无破图或控制台 404。
- 开启“减少动态效果”系统偏好时，特效仍以静态首帧安全呈现，不影响行动与结算。

## 6. 风险与回退

| 风险 | 控制方式 |
| --- | --- |
| 测试战斗敌人无对应美术 | `artId` 为空时只显示现有文字卡片，不构造资源 URL |
| Boss 核心与支援位资源混淆 | 由后端显式传递 `artType/artId`，前端不从名称或 `unitId` 猜测 |
| 图片影响窄屏布局 | 立绘容器限制尺寸，沿用现有 768px 响应式断点后手动检查 |
| 表现改动影响战斗逻辑 | 仅消费快照与事件；不修改行动提交、结算或 BattleEngine |

## 7. 交付物

- 战斗快照展示标识及其后端测试。
- 战斗立绘、修正后的特效播放和相应前端类型检查。
- 10 张缺失的被动技能书图标。
- 首页、队伍、新游戏、宠物详情的既有资源复用。
- 更新 `README.md`、`AGENTS.md`、`docs/development/DEVELOPMENT_STATUS.md` 中的阶段 14 美术验收状态；如新增前端资源约定，再更新 `docs/development/FRONTEND_STANDARDS.md`。
